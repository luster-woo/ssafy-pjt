# 📈 AI 기반 투자자 반응 분석 및 댓글 증강 서비스 (PJT 06)

이번 프로젝트에서는 **Django**와 **Selenium**을 결합하여 외부 금융 서비스의 실시간 데이터를 수집하고, **LLM(gpt-5-nano)** 파이프라인을 통해 정제 및 증강된 투자 정보를 제공하는 웹 서비스를 구현하였습니다.[cite: 5, 6]

## 🚀 주요 구현 기능

*   **실시간 동적 크롤링 파이프라인**: **Selenium WebDriver**를 활용해 토스증권의 검색 및 커뮤니티 페이지에 접속하여 실시간 투자자 댓글 20개를 자동으로 수집하는 로직을 구축했습니다.[cite: 6]
*   **통계적 데이터 정제(IQR)**: **Pandas**를 연동하여 수집된 댓글의 길이를 분석하고, **IQR(Interquartile Range)** 방식을 적용해 지나치게 짧거나 긴 이상치 데이터를 자동으로 필터링하여 데이터 품질을 높였습니다.[cite: 6]
*   **LLM 기반 데이터 증강 및 요약**: **OpenAI API**를 호출하여 원본 댓글의 의미를 유지한 채 격식 있는 문장으로 **증강(Augmentation)**하고, 전체 댓글을 분석하여 투자 심리 3줄 요약 결과를 생성하도록 구현했습니다.[cite: 6]
*   **SSE(Server-Sent Events) 실시간 진행 상황**: 데이터 수집부터 AI 분석까지의 복잡한 과정을 사용자가 웹 화면에서 실시간으로 확인할 수 있도록 **스트리밍 로그 출력 기능**을 도입했습니다.[cite: 6]
*   **통합 데이터 관리 시스템**: 실제 매칭된 공식 종목명과 각 단계별(**원본, 정제, 증강**) 데이터를 DB에 영구 저장하여 마이그레이션 및 추후 데이터 활용이 가능하도록 설계했습니다.[cite: 6]

## 🛠️ 개발 중 직면한 문제 및 대처

*   **동적 웹 요소의 비동기 로딩**: 토스증권의 검색 리스트와 커뮤니티 댓글이 로딩되는 시점이 일정하지 않아 크롤러가 요소를 찾지 못하고 **TimeoutException**이 발생하는 문제가 있었습니다.[cite: 6]
    *   **대처**: `WebDriverWait`와 `expected_conditions`를 활용해 **명시적 대기(Explicit Wait)** 로직을 구축하고, 한 글자씩 타이핑하는 방식과 엔터키 백업 로직을 추가하여 검색 안정성을 확보했습니다.[cite: 6]
*   **상호 참조(Circular Import) 에러**: `views.py`와 `services.py` 사이에서 함수를 서로 참조하려다 파이썬 인터프리터가 모듈을 로드하지 못하는 **ImportError**가 발생했습니다.[cite: 5]
    *   **대처**: 모든 핵심 비즈니스 로직과 크롤링 기능 단위를 `services.py`로 완전히 분리하고, `views.py`는 이를 호출만 하는 **단방향 구조**로 프로젝트 구조를 재설계하여 의존성 문제를 해결했습니다.[cite: 5]

## 📝 느낀 점

*   **데이터 파이프라인 설계의 가치**: 단순히 데이터를 긁어오는 수준을 넘어, **수집-정제-증강-저장**으로 이어지는 전체 흐름을 하나의 파이프라인으로 구성하며 백엔드 아키텍처 설계 능력을 한 단계 높일 수 있었습니다.[cite: 5]
*   **데이터 품질 정제의 필요성**: 수집된 로우 데이터(Raw Data)에는 닉네임이나 의미 없는 단어들이 많아, 이를 **IQR 기법** 등으로 정밀하게 걸러내는 과정이 LLM 답변 품질에 얼마나 결정적인 영향을 주는지 체감했습니다.[cite: 5]
*   **실제 서비스 환경의 예외 처리**: 네트워크 지연이나 검색 결과 미존재 등 실제 운영 중 발생할 수 있는 다양한 **예외 상황(F111)**을 안내 메시지로 변환하여 출력하며, 개발자 관점이 아닌 사용자 경험(UX)을 고려한 설계의 중요성을 배웠습니다.[cite: 6]
