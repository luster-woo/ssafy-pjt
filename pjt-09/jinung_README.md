## - 기술적 난관 및 해결 과정 (학습 내용)

프로젝트 진행 중 겪은 주요 트러블슈팅 내용입니다.

1. **API 인증 및 주소 매핑 오류 (401/404):**
   * **현상:** 외부 OpenAI 서버에 직접 호출을 시도하여 인증 실패(401)가 발생하거나, 프록시 주소 조립 과정에서 경로 중복(404)이 발생함.
   * **해결:** 장고(Proxy)와 FastAPI 간의 라우팅 구조를 일직선으로 맞춤. 외부 호출을 GMS 내부 관문 주소로 정렬하고, `.env` 환경변수를 통해 API 키와 URL을 중앙 집중식으로 관리함.
2. **데이터 규격 불일치 (`undefined` 점수 오류):**
   * **현상:** 프론트엔드와 백엔드 간의 데이터 교환 규격(Message vs Prompt) 불일치로 채점 데이터가 `undefined`로 출력됨.
   * **해결:** `services.py`에서 장고의 시리얼라이저 데이터를 FastAPI의 `ChatScoreRequest` 모델(prompt, answer)에 맞게 변환하는 파싱 로직을 추가하여 데이터 흐름을 정규화함.
3. **이미지 생성 모델 호출 문제:**
   * **현상:** 채팅 모델(gpt-nano)로 이미지 생성을 시도하여 에러 발생.
   * **해결:** FastAPI에 별도의 이미지 전용 엔드포인트를 구현하고, 텍스트와 이미지 요청을 별도의 모델 서버 경로로 분기 처리하여 모델 혼선을 제거함.

## -. 느낀 점

* **구조 설계의 중요성:** 입출력 흐름이 명확한 Proxy 구조를 설계하면서, 단순 기능 구현보다 각 서버 간의 통신 규약을 맞추는 것이 서비스의 안정성에 직결된다는 점을 배움.
* **디버깅 능력:** 401, 404, 500 에러를 단계별로 해결하며 FastAPI의 미들웨어와 request 처리 구조에 대해 깊이 이해하게 됨.
* **사용자 경험(UX):** 상태창(로딩 애니메이션)과 같은 UI 구현이 사용자에게 시스템의 동작 과정을 시각적으로 전달하는 데 매우 중요하다는 점을 느낌
