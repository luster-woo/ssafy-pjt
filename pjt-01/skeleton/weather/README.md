1. 과제 개요

이번 과제에서는 OpenWeatherMap API를 사용해서
실제 날씨 데이터를 받아오고,
그 데이터를 파이썬으로 가공해 출력하는 과정을 진행했다.

또한 생성형 AI(ChatGPT)를 활용해
API 사용법을 질문하고,
AI가 설명한 내용이 공식 문서와 맞는지도 직접 확인해보는 것이 목적이다.

2. 사용한 환경

Python 3

requests 라이브러리

OpenWeatherMap API

생성형 AI: ChatGPT

3. 구현하면서 한 작업들
3.1 API 응답 구조 확인

처음에는 OpenWeatherMap API에서
어떤 데이터가 오는지 감이 잘 안 와서
응답 데이터를 그대로 출력해서 key 값들부터 확인했다.

parsed_data = response.json()
parsed_data.keys()


이 과정을 통해
main, weather, wind, sys 같은
주요 데이터들이 어떤 구조로 들어오는지 알 수 있었다.

3.2 필요한 데이터만 골라서 추출

전체 데이터가 너무 많아서
과제 요구사항에 맞게 main 과 weather 데이터만 따로 추출했다.

이때 weather는 리스트 형태라서
첫 번째 값(weather[0])을 사용해야 한다는 것도 알게 되었다.

3.3 데이터 한글화

API에서 내려주는 key 값들이 전부 영어라
보기 불편해서 한글로 바꿔서 새 딕셔너리를 만들었다.

예를 들어,

temp → 온도

humidity → 습도

description → 요약

이런 식으로 바꾸니까
출력 결과를 한눈에 이해하기 훨씬 쉬웠다.

3.4 섭씨 온도 추가

OpenWeatherMap API의 기본 온도 단위가 Kelvin이라는 걸 처음 알았다.
그래서 섭씨로 변환하는 함수를 따로 만들었다.

섭씨 = 켈빈 - 273.15


기존 온도 값 아래에
섭씨 온도 데이터를 같이 넣어서 출력했다.

이 과정에서
“API 데이터는 그대로 쓰기보다는 가공이 꼭 필요하다”는 걸 느꼈다.

4. 생성형 AI 활용 과정
4.1 AI에게 API 설명시키기

ChatGPT에게
OpenWeatherMap API가 뭔지,
Current Weather API가 어떤 역할을 하는지 질문했다.

설명은 꽤 잘 해줬지만,
“이게 진짜 맞나?”라는 생각이 들어서
공식 문서를 같이 확인했다.

4.2 공식 문서와 비교

비교해보니
Current Weather API는 현재 날씨만 제공하고,
3일 후나 7일 후 날씨는
다른 API(Forecast API, One Call API)를 써야 한다는 점을 정확히 알게 됐다.

이 과정을 통해
AI 설명을 그대로 믿으면 안 되고
공식 문서로 확인하는 게 중요하다는 걸 느꼈다.

4.3 날씨 관련 질문 구성

AI에게 다음과 같은 질문을 했다.

“부산의 일주일 후 날씨를 알기 위해서는 어떻게 요청을 보내야 하나요?”

AI는
Current Weather API로는 불가능하고
One Call API를 사용해야 한다고 설명해줬다.

이 덕분에
API마다 역할이 다르다는 걸 확실히 이해할 수 있었다.

5. 이번 과제를 통해 배운 점

API는 먼저 응답 구조부터 확인하는 게 중요하다

JSON 데이터는 생각보다 많이 중첩되어 있다

생성형 AI는 도움은 되지만
정답은 공식 문서에 있다

날씨 데이터는 그대로 쓰기보다는
사용자가 보기 좋게 가공해야 한다

6. 느낀 점

처음에는 그냥 코드만 따라 치는 과제인 줄 알았는데,
API 문서를 직접 보고
AI 설명이 맞는지 확인하는 과정이 생각보다 도움이 많이 됐다.

특히
“서울의 3일 후 날씨는 왜 안 되지?” 같은 의문이
API 종류 차이 때문이라는 걸 알게 된 게 가장 기억에 남는다.

앞으로 API를 사용할 때
AI 설명만 믿지 않고
문서를 같이 보는 습관을 들여야겠다고 느꼈다.
